# 银行值机日志批量识别

## 适用场景

对数据机房值机日志截图做批量 AI 读图识别，提取结构化时间数据，自动计算耗时，输出可直接粘贴到 Excel 的
Markdown 表格，以及供下游脚本消费的 JSON。

两类界面格式不同，**表头不能混用**：

| 界面 | 版本特征 | 备份对象 |
|---|---|---|
| 主行（本文以「XX银行」代称） | 5 节结构，双备份 | `数据库ogg2备份` + `数据库ogg4备份` |
| 村镇行 | 3 节结构，单备份 | `数据库ogg备份`（只有一条） |

> 「XX银行」是客户行名占位符，使用时替换为实际机构名称。

---

## 执行前准备

1. 确认目标机构（主行 / 村镇行）——两者字段与表头都不同。
2. 确认图片目录。约定为 `<项目根>/月报/<YY>年<M>月/` 下的两个子目录
   （主行图片目录名与村镇行图片目录名由使用者自定，如 `主行图片/`、`村镇图片/`）。
   项目根目录由环境变量 `MR_ROOT` 指定，未设置时用当前工作目录。
3. 用 `ls` 列出目录内全部图片，确认张数（正常应等于当月天数）。

---

## 识别规则（必须严格遵守）

### 核心原则
- **禁止修改识别出的数据**，异常数据只标注 ⚠️，不改正
- **禁止模板化、联想化填写**，必须逐张图一一识别，不得据前后日期推断缺失值
- **看不清就标「待核实」**，不得猜测或伪造

### 时间字段提取

**主行界面需提取：**
- 第 3 节「批量执行」→ **批量开始时间**
- 第 4 节「日切状态及时间」→ **日切完成时间**
- 第 5 节「数据备份检查」→ **仅**提取标签为「数据库ogg2备份」「数据库ogg4备份」下的
  备份开始时间与备份完成时间
  - ⚠️ 不得提取该节的「会计日期」字段（只有 YYYY-MM-DD，不是备份时间）
  - ⚠️ 不得提取 OGG 同步状态检查里的日期字段
- 第 6 节「批量结束时间」→ **批量结束时间**

**村镇行界面需提取：**
- 第 3 节「批量执行」→ **批量开始时间**
- 第 4 节「日切状态及时间」→ **日切完成时间**
- 第 5 节「数据备份检查」→ 「数据库ogg备份」下的开始/完成时间（只有一条）
- 第 6 节「批量结束时间」→ **批量结束时间**

### 精度规则
- 图片显示到分钟（`YYYY-MM-DD HH:MM`）→ 原样输出
- 图片显示到秒（`YYYY-MM-DD HH:MM:SS`）→ 一并提取到秒

## 执行流程

```
Step 1  列出全部图片，确认总数
Step 2  每次读 6 张（并行）
        ⚠️ 若主会话模型不支持读图（Read 报 "model does not support images"）：
        派并行子代理，每个读 6~7 张，要求返回严格管道分隔行
        `imageN.png|批量开始|日切完成|ogg2开始|ogg2完成|ogg4开始|ogg4完成|批量结束`
        （时间写完整 YYYY-MM-DD HH:MM[:SS]，禁止用「会计日期」等纯日期字段顶替）
Step 2.5 可疑行复核：对顺序违例、异常偏早/偏晚的行，派复核子代理逐字精读该图对应字段，
        明确回报「截图本身如此显示 / 确为误读」，两次一致才采信
Step 3  按规则整理为「每行一天」
Step 4  Python 计算耗时（分钟）：批量允许跨日；备份同日相减、不做跨日回绕
Step 5  逐行逻辑校验（含与上月实测区间对比）
Step 6  生成 Markdown 表格并标注异常
Step 7  保存 .md 到当月目录；同时输出机读 JSON（每家机构一个独立文件）
Step 8  提醒用户抽样核实异常数据
```

### 输出 JSON 约定

两家机构**分开存放，互不合并**：

- 主行：`主行bank_batch_YYYYMM.json`
- 村镇行：`村镇bank_batch_YYYYMM.json`

```jsonc
{
  "YYYYMMDD": {
    "XX银行": {                       // 或 "村镇银行"
      "批量开始时间": "2026-10-01 23:12",
      "批量结束时间": "2026-10-02 00:58",
      "耗时": 106,
      "日切完成时间": "2026-10-01 23:20",
      "ogg2备份时间": "…", "ogg2备份结束时间": "…", "ogg2备份耗时": 24,
      "ogg4备份时间": "…", "ogg4备份结束时间": "…", "ogg4备份耗时": 8,
      "异常": false,
      "ogg异常": false,
      "异常说明": "已明确原因时填写，未明确则不写"
    }
  }
}
```

⚠️ `异常` / `ogg异常` / `异常说明` **必须放在机构字典内部**（如上），放到日期层级会让下游附件1的红标静默失效。

## 耗时计算

```python
from datetime import datetime, timedelta

def calc_duration(start_str, end_str, allow_cross_day=True):
    """两个时间之差（分钟）。allow_cross_day=False 时负值原样返回（交给校验标异常）"""
    for fmt in ("%Y-%m-%d %H:%M", "%Y-%m-%d %H:%M:%S"):
        try:
            start = datetime.strptime(start_str.strip(), fmt)
            end = datetime.strptime(end_str.strip(), fmt)
            break
        except ValueError:
            continue
    else:
        raise ValueError("无法解析时间：%r / %r" % (start_str, end_str))

    diff = end - start
    if diff.total_seconds() < 0 and allow_cross_day:
        diff += timedelta(days=1)
    return round(diff.total_seconds() / 60)
```

## 数据校验规则

| 校验项 | 规则 | 异常处理 |
|---|---|---|
| 备份时间顺序 | 备份开始 ≤ 备份完成（**同日比较，不做跨日回绕**，负值即异常） | 标 ⚠️ |
| 批量时间顺序 | 批量开始 ≤ 日切完成 ≤ 批量结束（批量允许跨日回绕） | 标 ⚠️ |
| 批量耗时 | **动态基准**：以本机构上月实测区间为常规范围 | 明显偏离才标 ⚠️ |
| ogg 备份耗时 | 动态基准（同上） | 明显偏离才标 ⚠️ |
| 批量耗时极大值 | > 500 分钟 | 标 ⚠️ |
| 备份耗时极大值 | > 60 分钟 | 标 ⚠️ |
| 批量开始时间 | 常规在 23:00–23:40；22:00 前提前启动多为月末/结息/特殊处理 | 标 ⚠️ 并在备注注明提前启动 |

⚠️ **时序判读关键经验**：

- 「批量结束时间」**可能早于** ogg 备份完成时间（如结束 00:53 vs ogg2 完成 01:05）。这是截图真实显示，
  **不算异常**，切勿当顺序违例误标；村镇行界面同样可能出现批量结束早于 ogg 完成 1–5 分钟。
- 备份耗时必须同日相减。跨日回绕会把「结束早于开始」算成 1000+ 分钟的假值，掩盖真实异常。
- 日期「穿越」显示（如 ogg 开始记成次日 23:57、ogg 耗时 -1435 分钟）→ 大概率读到了下一日截图行或界面跨日残留，
  **标 ⚠️ 待人工核对原图，不臆断改正**。
- 日切完成时间大幅早于批量开始（>10 分钟）属异常待核，需复核子代理精读原图。

### 结构性变更（会改变校验基线）

机构合并/拆分、系统升级、批量流程改造等事件会让耗时整体跳变。遇到这类情况：

1. 不改动截图数据，只加注说明；
2. 在产出的 md 里用引用块写明：事件、发生日期、影响范围、**变更后的新常态区间**；
3. 变更后同型数据不再按变更前的旧区间判异常，校验基线一律用「上月实测区间」。

### 周期性业务规则（正常但会偏离常规）

- **季度结息**：每年 3、6、9、12 月的 **19 日预结息、20 日结息** → 这两天批量提前开始、结束时间相应延长，
  **属正常业务行为，不得标异常**，md 的【重要业务背景】应写明。
- **月末**：最后 1–3 天批量提前启动（如 22:00 / 22:10）、耗时略长，属月末处理特征。
- **节假日**：长假前后批量与备份时间可能整体移动，基线随之上移。

## 输出格式

### 主行表头（含 ogg2 / ogg4 双备份）

```markdown
| 日期 | 批量开始时间 | 批量结束时间 | 批量耗时（分钟） | 日切完成时间 | ogg2备份开始 | ogg2备份结束 | ogg2备份耗时（分钟） | ogg4备份开始 | ogg4备份结束 | ogg4备份耗时（分钟） |
```

### 村镇行表头（单一 ogg）

```markdown
| 日期 | 批量开始时间 | 批量结束时间 | 批量耗时（分钟） | 日切完成时间 | ogg备份开始 | ogg备份结束 | ogg备份耗时（分钟） |
```

时间统一 `YYYY-MM-DD HH:MM`，每日一行。

### 异常标注结构

表格之后按三段组织，**三态分开写**，不要把已明确原因的条目混进待核对列表：

1. **【重要业务背景】**（仅当月存在结构性事件时）—— 引用块说明事件、日期、影响、新基线
2. **⚠️ 异常说明（N 天）**—— 只列真正待人工核对的项，逐条编号：
   `日期 + 现象（哪个字段异常/顺序矛盾/数值偏离）+ 复核结论（截图原样 or 疑似误读）+ 请核实方向`
   已查明原因的就地写「**原因已明确：…**」
3. **备注（界面显示特征，原样记录非异常）**—— 避免下月重复误标
4. **统计口径注释**—— 均值是否含异常值、剔除后均值、有效天数

其他要点：
- 每日一条只标一处主异常，避免同一行重复多条造成噪音
- JSON 同步三态：`异常: true`（待核对/未解释）、`"异常说明"`（已明确原因）

### 文件命名

- 主行：`主行值机日志（含耗时）.md`
- 村镇行：`村镇值机日志（含耗时）.md`
- 保存到当月目录（如 `26年10月/`）
