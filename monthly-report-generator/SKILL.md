# 月报自动生成 Skill

## 概览

完整流程：**先产出附件，再从附件读取数据渲染月报**。

```
值机日志截图 ──AI识别──→ 附件1 Sheet1「数据库备份详情」
工作量记录Word ──解析──→ 附件1 Sheet3「接听电话详情」
数据库导出表  ──手动/半自动──→ 附件1 Sheet2「4大系统交易量详情」
                     ↘
附件1.xlsx + 附件2排班表.xlsx ──读取──→ 月报 Word
                     ↗
上月排班表 ──续接生成──→ 附件2排班表.xlsx
```

### 目录与环境约定

- 项目根目录由环境变量 **`MR_ROOT`** 指定；未设置时取当前工作目录。
- 每月一个目录，短年份格式：`26年10月/`（不是 `2026年10月/`）。
- 排班表放在**上个月**的目录里：`26年5月/附件2《26年6月排班表》.xlsx`（5 月目录放 6 月排班表）。
  原因是月底就要先出下月排班，此时当月月报还没开始做。
- 本 skill 自带模板兜底副本：`templates/月报V2模板.docx`；也可用环境变量 `MR_TEMPLATE` 指定自己的模板。

## 一、月报格式：V2 五章结构

V2 结构（**5 章，没有「本月处罚情况」章**）：

| 章 | 小节 | 数据来源 | 自动/手动 |
|---|---|---|---|
| 一、本月项目概况 | 2 段 | 第 1 段固定；第 2 段由交易/电话/巡检汇总 | ✅ 自动 |
| 二、人员投入与考勤 | （一）人员配置与值班安排 | **固定正文** | — |
| | （二）本月人员值班考勤情况 | 日历 + 请假/调班记录 | 半自动 |
| | （三）人员变动情况 | **固定正文** | — |
| | （四）XX月排班计划 | 附件2 排班组数汇总 | ✅ 自动 |
| 三、本月主要工作完成情况 | （一）系统交易监测情况 | 附件1 Sheet2 | ✅ 自动 |
| | （二）业务来电与问题解答记录 | 附件1 Sheet3 | ✅ 自动 |
| | （三）数据机房值班巡检 | 巡检记录 | ❌ 手动 |
| | （四）日终批处理监测情况 | 附件1 Sheet1 | ✅ 自动 |
| 四、安全保密与数据安全 | 2 段 | **固定正文** | — |
| 五、附件 | 「加附件」占位 | 人工插图 | ❌ 手动 |

> 旧的多章「手动格式」已退役，不要再用它产出成品。

### 自动 vs 手动

| 环节 | 自动/手动 | 说明 |
|------|-----------|------|
| 附件1 Sheet1 数据库备份详情 | ✅ 自动 | 值机日志识别结果直接写入 |
| 附件1 Sheet2 4大系统交易量 | 🔧 半自动 | 表头和日期自动，交易量需数据源（数据库导出表） |
| 附件1 Sheet3 接听电话详情 | ✅ 自动 | 工作量记录解析结果直接写入 |
| 附件2 排班表 | ✅ 自动 | 按轮转规律续接生成 |
| 月报-交易监测 | ✅ 自动 | 从附件1 Sheet2 读取 |
| 月报-电话统计 | ✅ 自动 | 从附件1 Sheet3 读取 |
| 月报-批处理 | ✅ 自动 | 从附件1 Sheet1 读取 |
| 月报-排班统计 | ✅ 自动 | 从附件2 读取 |
| 月报-人员请假 | 🔧 半自动 | 天数自动；请假人/日期/天数由人工提供后写进 `attend` |
| 月报-巡检事件 | ❌ 手动 | 人工提炼成 [标题, 时间, 详情, 解决方案] 四元组填 `alerts` |

## 二、执行流程 A：生成排班表（独立）

触发词：`生成X月排班表` / `生成排班表`

1. 取月份与年份（默认当前年份）。
2. 自动查找上月排班表：生成 7 月排班表 → 找 6 月排班表 → 在 **5 月**目录。
3. 按续接规律生成，存到「上个月目录」。

```bash
MR_ROOT=/path/to/项目根 python3 scripts/generate_schedule.py <月份> <年份> \
    [上月排班表路径] [输出路径]
```

排班规律：
- **3 白 → 3 中 → 3 夜 → 3 休**（12 天一个周期），任何时刻 3 组上班、1 组休息
- 4 组人员分组写在脚本的 `GROUPS` 常量里，按自己班组替换
- 现场项目经理（常班）按国家节假日排班（`chinesecalendar`）：工作日上班、节假日休息、调休日上班
- 从上月最后一天的排班续接
- **休息日底纹**：休息日（周末 + 法定节假日）整行加淡蓝底纹 `#B6C7EA`；
  工作日（含调休上班的周末）无底纹

## 三、执行流程 B：生成月报（完整流程）

### 第一步：确认月份与文件

1. 取月份；未指定则用当前月份的上一个月
2. 定位目录 `<MR_ROOT>/月报/<YY>年<M>月/`
3. 检查：值机日志截图目录、`值班工作量记录<YYMM>.docx`、上月排班表

### 第二步：识别值机日志 → 填入附件1 Sheet1

1. 用 `bank-log-recognition` 识别两家机构的截图
2. 当月已有识别 JSON 时**直接复用**，避免二次读图。脚本接受合并后的 batch JSON：
   ```bash
   # schema: {YYYYMMDD: {"村镇银行": {...}, "XX银行": {...}}}（两家日期取并集）
   python3 scripts/generate_attachment1.py <月份> <年份> batch_data.json phone_data.json
   ```
   ⚠️ 识别产出保持**两家独立文件**，这里的合并只是喂给附件1脚本，不改动识别产出
3. 异常数据用红色标记

**Sheet1 结构**（以 31 天月为例）：

| 区块 | 行 | 说明 |
|---|---|---|
| 村镇行表头 | 1–2 | 合并 B1:H1 |
| 村镇行数据 | 3–33 | A=日期, B=批量开始, C=批量结束, D=耗时, E=日切完成, F/G/H=ogg 开始/结束/耗时 |
| 平均行 | 34 | B=时刻均值（预计算），D/H=AVERAGE |
| 空行 | 35 | — |
| 主行表头 | 36–37 | 合并 B36:K36 |
| 主行数据 | 38–68 | 含 ogg2（F–H）与 ogg4（I–K） |
| 平均行 | 69 | B=时刻均值（预计算），D/H/K=AVERAGE |

> 30 天月份平均行前移一行（村镇 33 / 主行 67）。脚本按天数自动算，读值前先确认行号。

**字段映射**：批量开始→B、批量结束→C、耗时→D、日切完成→E、ogg 开始/结束/耗时→F/G/H；
主行另加 ogg2（F–H）、ogg4（I–K）。

### 第三步：解析工作量记录 → 填入附件1 Sheet3

用 `workload-record-parser` 解析，写入 Sheet3「接听电话详情」：

- 行 1 表头（A=日期，B–L=11 类问题）
- 行 2 起为每日数据；末两行为「各类问题小计」「处理问题总计」

**电话分类（11 类）**：柜员强制签退、终端变更、数据查询业务、人为操作失误、设备故障异常、
系统异常故障、银行业务问题、机房环境、服务器设备问题、网络设备问题、基础设施问题。

### 第四步：生成附件1 Sheet2 表头与日期

- 自动建表头和日期行
- **交易量留空**，提示用户填写（数据源通常是数据库导出的交易量明细表，
  字段为 CALCULATE_DATE / 核心系统 / 网联系统 / 银联系统 / 支付系统 / 总计）
- 含 SUM / AVERAGE 公式

### 第五步：生成附件2排班表

见流程 A。按 3 白 → 3 中 → 3 夜 → 3 休 续接上月。

### 第六步：提示用户填写交易量

告知附件1 Sheet2 已建好表头与日期，填完说「继续生成月报」。

### 第七步：从附件1 + 附件2 取数 → 渲染月报 Word

#### 7.1 取数口径（照此计算，不要另立口径）

| 月报字段 | 来源 | 算法 |
|---|---|---|
| 交易合计/核心/支付/网联/银联 | 附件1 Sheet2 | 四列逐列求和；**四项之和必须等于合计**，不等就是表里有脏行，先查 |
| 接听总数 | 附件1 Sheet3 | 11 类逐列求和后相加（不是只数日期行） |
| 各类电话数量/占比 | 附件1 Sheet3 | 逐列求和；占比 = 该列 / 总数 × 100，保留两位，**按占比降序** |
| 批量平均开始时间 | 附件1 Sheet1 | 平均「仅时刻」的分钟数；**时间 < 12:00 视为跨日，先 +1440 分钟再平均**（否则会算出 18:37 这类假值） |
| 批量平均耗时 | 附件1 Sheet1 | 耗时列直接 AVERAGE，同日相减、不回绕 |
| 排班白/中/夜班次 | 附件2 | 各小组该列求和；平均工作天数 = 总工作天数 / 4 |
| 值机天数/班次 | 日历 | 天数 = 当月自然日；班次 = 天 × 3（4班3倒）或 × 2（白夜休休） |

#### 7.2 组装当月数据 JSON

按 `scripts/v2_report_schema.json` 的字段填，文件里有完整字段说明与一份虚构示例。

**文案部分要自己写**（不是机器拼接）：
- `attend`：把请假人、日期、天数、代班人写清楚；有调班时填 `shift_para`
- `alerts`：从巡检记录提炼成 [标题, 发生时间, 问题详情, 问题解决方案] 四元组，编号自动生成；无预警填 `[]`
- `alert_summary`：一两句话概括本月预警，供概况段使用
- `batch[4]`：只有季度结息（3/6/9/12 月 19–20 号）、机构调整等特殊情况才写说明，平时填 `null`

#### 7.3 渲染

```bash
MR_ROOT=/path/to/项目根 python3 scripts/render_v2_report.py <当月数据.json>
```

可选参数：`--root`（月报根目录）、`--out`（覆盖输出路径）、`--template`（换模板）。
JSON 顶层写成数组可一次渲染多个月。

渲染器做的事：复制模板段落 XML 生成正文 → 重建标题书签 → 替换目录「（四）XX月排班计划」→
注入 `updateFields` 让 Word 打开时自动刷新目录页码。模板与原始月报只读，输出为新文件。

### 第八步：输出结果

1. 说明哪些章节已自动填充、哪些需人工补充（巡检事件、五、附件）
2. V2 模板**不使用红色占位符**：巡检章无内容时输出「本月机房巡检环境正常，未发现需上报的预警事件。」；
   第五章保留「加附件」，由人工插图
3. 用文件预览展示生成的 docx
4. 提醒：目录页码在 Word/WPS 打开时自动刷新，首次打开若询问是否更新域，选「是」

## 注意事项（踩过的坑）

1. **附件1是产出物不是数据源**：先生成附件1，再从附件1读数据。
2. **附件1 Sheet2 交易量需要数据源**：只建表头和日期，交易量来自数据库导出表。
3. **排班表存放在上个月目录**，与命名规则一致。
4. **排班续接**：3 白 → 3 中 → 3 夜 → 3 休（12 天一周期），从上月最后一天续接。
5. **人员分组固定**：写死在脚本 `GROUPS` 常量，人员变动要同步改。
6. **异常数据红色标记**：值机识别中的异常行在附件1 用红字。
7. **★ AVERAGE 不能用于时间列**：附件1 的时间单元格是**含日期的完整 datetime**，
   `=AVERAGE(B3:B32)` 会算成「日期偏移均值 + 时刻均值」，30 天月份直接偏 12 小时
   （23:14 会显示成 11:14）。平均开始时间必须**预计算仅时刻均值后写静态值**
   （脚本已内置 `avg_time_of_day()`）。
8. **批量时间跨日**：开始时间 < 12:00 的一律视为跨日，求平均前 +24 小时。
9. **平均行公式缓存坑**：平均行写的是 `=AVERAGE(...)` 公式，而读值用 `data_only=True`——
   openpyxl 不计算公式。若附件1 从未被 Excel/WPS 打开保存过，平均行读到的是 None。
   正常流程中用户填 Sheet2 并保存会刷新缓存；脚本直写值时需手算覆盖平均行，
   或先 `soffice --headless --convert-to xlsx` 重算再生成月报。
10. **休息日底纹**：休息日整行 `#B6C7EA`，工作日（含调休上班的周末）无底纹。
11. **改文档前先 `lsof` 确认用户没在 WPS/Office 里开着**：否则用户端保存时会用内存副本整份回写，
    把脚本写入的修改静默冲掉。可靠顺序 = 请用户关闭文档（不保存）→ 写入 → 用户重新打开核对。
12. **本地 editor_sdk 导出会损坏 xlsx**：出现过公式变 `==SUM(...)` 双等号、红标丢失。
    对 xlsx 的小幅确定性改动**直接用 openpyxl**，改前先 `cp` 备份。
13. **月报里不写改进措施/建议**：只陈述事实与数据。跨职责的优化转成对甲方的诉求
    （「建议由甲方……」），不要写「我司将……」，否则等于给自己派活。
14. **结构性事件要分段表述**：当月若发生机构合并/系统升级等导致耗时口径变化的事件，
    「日终批处理监测」不能只报单值平均——按事件前后分段写，并注明均值是否剔除异常日。
