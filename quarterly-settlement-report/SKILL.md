# 季度结算报告生成 Skill

> 对象：XX银行科技运维服务项目人员外包合同 · 阶段（季度）结算报告
> 前身：月度报告。本 Skill 只做「月报 → 季度结算报告」这一步，不产月报。
> 「XX银行」为占位符，使用时替换为实际机构与项目名称。

## 一、铁律（违反即返工）

1. **模版唯一**：以一份已定稿的结算报告 docx 为唯一格式模版。skill 自带快照见
   `assets/季度结算模版.docx`；也可用环境变量 `QS_TEMPLATE` 指向自己的模版。
   **改了模版就要换快照**——脚本按**段落索引**写入，模版结构一变必须同步 `scripts/build_quarterly.py` 的 `IDX`。
2. **固定章节逐字照抄**：报告末尾三章（目标完成情况 / 安全保密与数据安全 / 签字盖章栏）为固定模版，
   不允许改写、增补、调整语序；只有付款阶段标签「本付款阶段（20XX 年 QX）」按季度替换。
3. **不体现处罚/罚款**：任何版本的报告都不得出现「处罚情况」「罚款」等内容，旧报告里有的也不搬、不补。
   `verify_quarterly.py` 把这条当硬校验。
4. **数值一律来自月报/附件1**，不手工转抄：脚本自动解析并求和，人工只写文字性内容（请假、预警清单等）。
5. **源文件只读**：历史季度报告、月报原始件一律不改；新报告另存新文件名。
6. **改文档前先 `lsof` 确认没在 WPS/预览里开着**（开着就请用户关闭，否则会被内存副本整份回写冲掉）。

## 二、季度划分（周期以合同起租日为界）

示例按 **26 日切**（合同起租日为 26 日）：

| 季度 id | 报告周期 | 附件月报 | 份数 |
|---|---|---|---|
| 2025Q4 | 2025/09/26–2025/12/25 | 9、10、11 月 | 3 |
| 2026Q1 | 2025/12/26–2026/03/25 | 12、1、2 月 | 3 |
| 2026Q2 | 2026/03/26–2026/06/25 | 3、4、5 月 | 3 |
| 2026Q3 | 2026/06/26–2026/09/25 | 6、7、8、9 月 | **4** |

> 因为「周期按 26 日切、月报按自然月」，Q4 必然带 4 份月报，这是既定口径。
> 起租日不是 26 日时，按合同实际起租日调整 `period_start/period_end`。
> 付款阶段标签 = 周期起始月所在日历季（9/26 起 → 当年 Q4）。

## 三、数据口径

**全部按「报告周期」逐日统计**，数据源是附件1 逐日明细，不是月报合计数。

| 项目 | 口径 | 来源 |
|---|---|---|
| 值机天数 | **= 报告周期自然天数**（如 91/90/92/92） | 周期推算 |
| 班次 | 各月排班班次 × 该月落在周期内天数 ÷ 该月月报覆盖天数 | 月报 §二 + 周期 |
| 巡检次数 | **= 班次数**（每班次 1 次交接班巡检） | 推算 |
| 四大系统交易 | 附件1「4大系统交易量详情」逐日求和（只取周期内日期），四项和须等于合计 | 附件1 |
| 电话总数 / 分类 | 附件1「接听电话详情」逐日求和；占比 = 单项 ÷ 周期电话总数 | 附件1 |
| 预警起数 | 各月月报「预警N」中**发生时间落在周期内**的条数（边界月也要读） | 月报 §三(三) |
| 批量耗时 | 周期内逐日耗时的**算术平均**（不给区间） | 附件1 备份表 |
| 「核心保障进度」月份跨度 | 按**报告周期**取（3/26–6/25 → `03-06 月`） | 模版同源 |
| 「文档交付 / 报表编制」月份 | 按**附件月报**月份取（3、4、5 月） | 附件 |

## 四、执行流程

```bash
SK=~/.workbuddy/skills/quarterly-settlement-report
export MR_ROOT=/path/to/项目根

# 1) 先干跑，核对取数（不写文件）
python3 $SK/scripts/build_quarterly.py --quarter 2026Q3 --dry-run

# 2) 正式生成（写回 季度结算/<季度目录>/<文件名>.docx）
python3 $SK/scripts/build_quarterly.py --quarter 2026Q3
#    或用 --out /tmp/xx 先出草稿

# 3) 复核：把报告里的每个数字回到月报周期口径重抽一遍对撞，并检查无处罚字样
python3 $SK/scripts/verify_quarterly.py --quarter 2026Q3
#    必须打印「全部一致」才可交付
```

**新季度怎么做**（月报齐全后）：

1. 打开 `data/quarters.json`，在 `quarters` 数组末尾追加一条：

```json
{
  "id": "2026Q4",
  "folder": "2026年9-10-11",
  "out": "XX银行股份有限公司科技运维服务项目-季度结算-2026年Q4.docx",
  "period_start": "2026-09-26",
  "period_end": "2026-12-25",
  "qlabel": "2026 年 Q4",
  "months": ["2026-09", "2026-10", "2026-11"],
  "narratives": {}
}
```

2. `--dry-run` 一遍：数字应全部自动出来，控制台会提示「⚠ 请假段、预警清单、批量耗时说明 为自动草稿」。
3. 把草稿润色后写进 `narratives`（字段见下表），再正式生成。
4. `verify_quarterly.py` 必须「全部一致」。

**narratives 字段**

| 键 | 作用 | 缺省行为 |
|---|---|---|
| `startup` | 首季追加「项目启动阶段、首名人员入场、完成团队组建」 | 不加 |
| `new_task` | 第二章「本周期内新增 XX 监控」句 | 空 |
| `leave` | 第三章（一）请假整段 | 从月报请假句自动拼草稿 |
| `extra` | 第三章（三）额外协作任务 | 「外来人员接待登记、年度资产盘点」 |
| `warn_list` | 表格「机房巡检与问题处置」的事件枚举（以「等事件」结尾） | 用各月预警标题自动拼接 |
| `sys_note` | 表格「日常系统监测」整段 | 通用平稳表述 |
| `batch_note` | 表格「日终批处理」耗时说明 | 自动写「村镇 X-Y 分钟、主行 X-Y 分钟」 |

> 预警事件较多时要**人工合并同类项**，保证枚举条数与「处置预警信息 N 起」对得上，
> 不要让读者数出缺口。

## 五、月报依赖

- **月报 docx**：`<MR_ROOT>/月报/<YY>年<M>月/*-V2.docx` —— 取班次数、请假句、预警标题与发生时间；
  边界月份（如 2026Q1 的 3 月）虽不是本季附件，也要读。
- **附件1 xlsx**：`<MR_ROOT>/月报/<YY>年<M>月/附件1*.xlsx` —— 取逐日交易、逐日电话、逐日批量耗时。
  若某月数据合并进了相邻月的跨月表（如 9 月数据在 10 月的「9-10 月」表里），
  在 `scripts/period_data.py` 的 `ATT1_OVERRIDE` 里登记例外。

解析逻辑集中在 `scripts/period_data.py`（三张表的表头/分块定位）与 `build_quarterly.py`（班次折算、预警过滤）。
表结构若改版，先跑一遍 `period_sum` 与月报合计对账，对得上再出报告。

月报本身由 skill `monthly-report-generator` 产出（V2 五章结构）。缺失或缺日时先补月报，再跑本 Skill。

## 六、历史坑

- **★ 数据按周期、附件按整月，两者必然对不上**
  月报按自然月、周期按起租日切。对方每月都要收到月报，所以季度附件会包含 4 份月报；
  但报告只算周期内的那些天 → **季度数 ≠ 各月月报之和**。正文必须加一句说明：
  「附件为各月整月月度报告，本报告所列数据按报告周期（…）统计」。
  **绝不能**把整月合计（如「值机 122 天」）写进周期报告。
- **班次折算不能用自然月天数做分母**：若某月月报只覆盖部分天（如 9 月只覆盖 9/26–9/30 共 5 天、10 个班），
  分母必须取「月报覆盖天数」，否则该季会漏算班次。
- **预警要按发生时间过滤**：周期开始前的预警属上一季，必须剔除；边界月反过来要读，
  即使它不是本季附件。
- **附件1 逐日与水印数据不一致时以逐日为准**：遇到过漏算最后一天、电话逐日与小计差 1–2 的情况。
- **不能用 `AVERAGE` 之类的表内公式**：本报告全静态值，避免 openpyxl/WPS 不重算导致错值。
- **段落索引写死**：模版增删段落必须改 `IDX`，否则文字会串位（尤其是固定三章与附件清单）。
- **附件清单条数自适应**：3 个月报删掉第 4 条（段落数 -1），4 个月报保留；删除后末尾空段索引前移属正常。
- **生成后不要再用 editor_sdk 通道导出**（会把公式变 `==`、丢红字标记）；本 Skill 全程 openpyxl/docx 直写。
- 交付前把对应月报复制进季度目录（附件与报告同目录），命名保持 `…-V2.docx` 原名。
